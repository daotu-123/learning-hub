## 0.1 三个正交维度（术语消歧）

> 旧文档把「形态 A/B/C」同时用于**代码组织**和**部署形态**，导致过误读（mech-qbank 已踩过一次）。
> 本项目的三个维度互不蕴含，分别定案：

| 维度 | 结论 | 含义 |
|---|---|---|
| **代码组织** | **并行** | `androd-app` 与 `mech-qbank` **各自独立演进**：不合并后端、不共享用户体系、不建跨项目外键 |
| **部署** | **公网单用户** | 一台 VPS + 域名 + TLS，owner 自用；手机与浏览器登录后共享同一份数据。**部署资源 owner 本周内到位** |
| **身份模型** | **单账号** | 部署时创建账号；Argon2id 存口令；服务端签发短时、可撤销会话令牌。**不做注册、不做游客、不做多租户** |

> 注意：题库按 §0.3 **以「服务」方式被学习中枢调用**，这是运行时依赖，**不是**代码合并，
> 与「代码组织=并行」不冲突。

## 0.2 产品边界（owner 逐项决定）

| 模块 | 决定 | 落地要求 |
|---|---|---|
| **首页** | **一句话日报 + 入口卡片**（AB 结合） | 顶部只放 1–3 个数字（今日复习/新学/错题），下面少量入口；**不铺满详情卡片** |
| **日记 / 待办** | 正文**只在电脑 Obsidian 改**；手机只做「今日视图 + 勾选完成」 | 保留 Obsidian 双向同步；手机端**不提供正文编辑器**；已发布的「勾选」链路（`/api/hub/task`、`review-done`）不变 |
| **番茄钟 / 复习 / 计划** | **保留**，并入学习中枢 | 现有 `desk/DeskPomodoro` 与 `hub/FocusView` 是重复实现，**只留一份**（以 hub 为主） |
| **健康（睡眠 / 运动）** | **删除，不做** | 数据源是手环，App 不再承担记录与展示。见 §0.5 删除清单与波及面 |
| **照片同步** | **保留** | 手机拍照 → 上传 → 落 Obsidian「工作台照片/月/」，这是高频刚需 |
| **收藏（抖音 / 小红书）** | **保留**，改为「收件箱」入口 | 不再占一个底部 Tab；作为学习中枢里的一个入口页 |
| **设置（壁纸 / 服务器地址）** | **降级为二级页** | 不进底部 Tab；从「我的/设置」进入 |
| **底部导航** | **只留 2 个 Tab：学习中枢 / 题库** | 取消现在的 3 Tab 与 `DeskPage` 自带导航（双层 Tab 是体验差的直接原因） |
| **AI 助手** | **保留**，prompt 改为学习专用 | 现 9 个快捷问题里含健康/使用时长，随健康模块一并清理 |

## 0.3 题库：服务化（owner 选 A）

| 项 | 决定 |
|---|---|
| 唯一题库服务 | **`mech-qbank`**：唯一服务端、唯一数据源、唯一判分/排期实现（公网部署） |
| 学习中枢的题库 | **降级为客户端**：调用 MQ 的服务，不持有题库逻辑 |
| 代码 | 删除 `web/src/qbank/` 全部副本（2151 行，占前端 34%）；移除 `element-plus` 打包（APK 省 ≈640KB） |
| 数据产物 | 废除「构建期手工拷贝 `qbank-data.js`」；学习中枢不再产出题库数据副本 |
| 离线 | **接受副作用**：服务化后题库需联网。离线缓存列为**后续增强，不在本轮** |
| 边界 | 不得因服务化而合并两仓库后端 / 共享用户表 / 建跨项目外键（见 §0.1） |

> 由此产生的依赖：**学习中枢的题库功能依赖 MQ 服务在线**。
> 因此 `mech-qbank` 的公网部署与鉴权是学习中枢题库可用性的前置条件，需与其进度对齐。

## 0.6 离线 / 在线差异（Gate 0 条件 3 的答案）

| 能力 | 在线（LAN / 公网） | 离线 |
|---|---|---|
| 学习中枢（今日/计划/复习/反馈/专注/课堂） | 全走 HTTP，正常 | **不可用**（保持现状） |
| 工作台（日记勾选、任务、番茄、照片、收藏、AI） | 全走 HTTP，正常 | **不可用**（保持现状） |
| 题库 | 服务化后走 MQ 服务 | **本轮起不可用**（离线缓存为后续增强） |
| APK 热更新 | 拉清单 → 逐文件 sha256 校验 → 写盘 → 重载 | 失败保持内置旧版（不回滚半更新） |
| 数据写入 | 由服务端写 Obsidian vault / JSON / SQLite | 手机端不直写 vault |

## 0.7 授权边界（可直接当验收标准）

**明确不做（做了即越权）**
1. 不做多租户、不做注册流程、不做游客模式、不加 `user_id` 列
2. 不合并 `androd-app` 与 `mech-qbank` 的后端 / 用户表 / 跨项目外键
3. 不改 MQ 的判分与 FSRS 排期行为；学习中枢侧不再保留任何判分实现
4. 不动 `.gitignore`；不移动 `server/web_dist`；不移除热更新 sha256 校验
5. 不在日志中保留明文令牌；不把长期令牌写入 localStorage
6. 不删除或覆盖用户数据（Obsidian / JSON / SQLite）——任何迁移先过 Gate 2a
7. 不保留健康模块的任何入口、状态或读写路径（除 §0.5 登记的历史数据）

**本次要做**
1. 配置化（绑定地址/端口/vault 路径/令牌来源全部走配置，默认值保持本机行为）
2. `/api/v1` **兼容迁移**：旧 `/api/*` 保留别名，覆盖已发布 APK 的一个版本周期
3. 身份升级：单账号 + Argon2id + 服务端会话令牌（可撤销）+ 登录页
4. 令牌卫生三通道：日志脱敏 / Referer 策略 / 不生成含令牌的可分享链接
5. 速率限制与登录退避，正确处理 `X-Forwarded-For`
6. `/health/live`、`/health/ready`；结构化日志（request_id，不含正文/口令/token）
7. 模块化拆分（`routers/`），静态托管与中间件分离
8. 题库服务化：删除前端副本，改为调用 MQ 服务
9. 产品边界落地：2 Tab、首页日报、健康删除、设置二级页、收藏收件箱
