# Windows 部署指南（从零到可用）

面向的场景：**vault 继续留在家用 PC，服务也跑在家用 PC，只是通过隧道/反代把
web 端暴露到公网，手机 4G 能打开**。不做任何数据迁移。

三条路径任选其一（本文按 Tailscale Funnel 展开，另两条见文末）：

| 方案 | 适合 | 需要什么 |
|---|---|---|
| **A. Tailscale Funnel**（推荐先试） | 没有公网 IP、想最快跑通 | 已装 Tailscale + 浏览器点一下开通 Funnel |
| **B. Cloudflare Tunnel** | 有自己的域名，想完全自控 DNS | 域名托管在 CF + 一个 CF 账号 |
| **C. Caddy 直连** | 有公网 IP、想自己管证书 | 域名 A 记录指向本机 + 80/443 未被占 |

---

## Step 0：核对构建产物（**不要跳过**）

`*.exe` 在 `.gitignore` 里，产物从不进版本控制——git 里没有任何信息能告诉你
`exe\` 里躺着的是哪一次构建。P1-1 那次重打就撞上过：`exe\` 里的产物停在 10-18，
落后代码两个里程碑（没有 `/health` 端点、不认 `HUB_PORT`/`HUB_DATA_DIR`），
而构建日志是**成功**的，因为那份根本不是这次构建的产物。

所以每次部署先核对：

```bat
type exe\VERSION
```

```
# LearningHub build manifest (generated by server/build-version.ps1)
# generated_at=2026-10-21 17:55:20 +08:00
commit=199b648
tree=199b648-clean
count=3
artifacts=LearningHubManage.exe (15,586,649 B, 2026-10-21 17:55); ...
```

**两个字段都要看**：

- `commit=` 是不是你期望上线的那个提交（`git log -1 --format=%h`）
- `tree=` 是不是 `-clean`。带 `-dirty-N-files-changed` 说明打包时工作区有未提交
  改动，**这份 exe 不对应任何一个 commit，别拿去部署**

## Step 1：准备目录

```
C:\LearningHub\
├─ exe\                      ← 从仓库 exe\ 整个拷过来（含 VERSION）
├─ data\                     ← 数据目录，**必须显式指定**
└─ logs\                     ← 日志，Step 3 会自动建
```

`data\` 里会长出这些（备份脚本就是按这个清单备的）：

| 文件 | 是什么 | 丢了会怎样 |
|---|---|---|
| `account.json` | 账号的 Argon2id 哈希 | **要重新建账号**，会话全失效 |
| `sessions.json` | 会话令牌哈希 | 全员重新登录 |
| `media_url_secret` | 媒体签名密钥 | 已签发的照片 URL 全部失效 |
| `settings.json` | 设置、壁纸、访问令牌 | 设置回默认 |
| `usage.db` | SQLite：使用统计 / 番茄钟 | 历史数据丢失 |
| `wallpapers\` | 壁纸图片 | 需重新上传 |

## Step 2：建账号

**必须在装服务之前做**，且必须显式给数据目录：

```bat
cd C:\LearningHub\exe
set HUB_DATA_DIR=C:\LearningHub\data
LearningHubManage.exe set-password
```

输出里找这行（**P1-7 加的可审计落点**）：

```
目标数据目录：C:\LearningHub\data
账号已写入：owner
已写入：C:\LearningHub\data\account.json      ← 看这行确认落点
口令哈希已保存（Argon2id）；明文口令没有落盘，也没有打印。
```

⚠️ **不加 `HUB_DATA_DIR` 会怎样**：exe 会拒绝执行并打印退出码 2。
这是有意的防呆——打包版 exe 的缺省目录是"exe 同级 `data\`"，
那个位置通常不在备份脚本清单里。换句话说：**不加这个变量 = 建在了没人记得的地方**。

已经有账号要改口令时加 `--reset`（会撤销全部会话，所有设备重新登录）。

## Step 3：装服务

```powershell
cd E:\agent\androd-app\deploy
.\install-service.ps1 -DataDir C:\LearningHub\data -NoStart
```

不带 `-DataDir` 会直接抛错（同一个坑，再拦一次）。
脚本做的事：注册服务、设 `delayed-auto` 启动类型、配失败自动重启
（5s/30s/60s 三次）、把环境变量写进服务注册表。

**公网模式（走隧道时）**要额外加两个变量：

```powershell
.\install-service.ps1 -DataDir C:\LearningHub\data -NoStart
# 然后手工把这两条加进服务注册表，或直接改 install-service.ps1 的 $envPairs：
#   HUB_PUBLIC=1
#   HUB_TRUSTED_PROXIES=127.0.0.1     ← 隧道在本机时填 127.0.0.1
```

### 公网模式（`HUB_PUBLIC=1`）改了什么

| 项 | 平时 | `HUB_PUBLIC=1` |
|---|---|---|
| 监听地址 | `0.0.0.0` | `127.0.0.1`（TLS 由隧道终结） |
| UDP 自动发现广播 | 开 | **关** |
| 回环免令牌豁免 | 开 | **关** ← 最关键 |
| 数据目录 | 可缺省 | **必须显式指定**，否则拒绝启动（退出码 3） |

**为什么必须关回环豁免**：cloudflared / tailscale funnel 都是从
**本机 `127.0.0.1`** 连进来的。不关豁免的话，所有公网流量都被当成
"来自本机"，一个令牌都不用就能读全部数据。

代价是本机桌面端也要重新登录一次。若确实需要本机免令牌调试，
设 `HUB_LOCAL_BYPASS=1`——但启动横幅会打醒目警告，
**公网模式下开了它等于对公网开放无鉴权访问**，别在长期运行的服务上开。

不确定当前是不是公网模式时，看这两个地方：
启动横幅（`python main.py` 时）和 `<DataDir>\server.log` 里那条
`运行模式=… 监听=… UDP广播=… 回环免令牌豁免=… 受信代理=…`——
服务化部署走的是 uvicorn，**横幅一个都看不到，只有日志里有**。

## Step 4：打通隧道

### 方案 A：Tailscale Funnel（推荐先试）

**一次性开通（需要 owner 用浏览器做，本机做不了）：**

1. 浏览器打开 <https://login.tailscale.com/admin/dns>
2. 打开 **HTTPS Certificates**（Funnel 依赖它自动签发证书）
3. 浏览器打开下面这个链接，点启用（CLI 会直接把链接打出来）：

   ```
   tailscale funnel --bg <端口>
   → Funnel is not enabled on your tailnet.
     To enable, visit:
          https://login.tailscale.com/f/funnel?node=<你的节点ID>
   ```

   本机的实际链接是 `https://login.tailscale.com/f/funnel?node=neXoZHPc3u11CNTRL`
   —— 节点 ID 因机而异，以 CLI 当时打印的为准。

**开通后开通隧道：**

```bat
tailscale funnel --bg 8637
tailscale funnel status
```

访问地址形如 `https://chinami-qpsolag.<tailnet>.ts.net`
（`<tailnet>` 来自 `tailscale status --json` 的 `MagicDNSSuffix`，
本机是 `tail80a359.ts.net`）。

**必须同时确认服务端配了受信代理**，否则限流会把整个隧道算成一个 IP：

```
HUB_TRUSTED_PROXIES=127.0.0.1
```

**验证真实客户端 IP 是否取到**（这一步别跳）：

```bat
type C:\LearningHub\data\server.log | findstr /c:"GET /api/summary"
```

看 access 日志里的来源地址：应该是**手机的公网 IP**，不是 `127.0.0.1`。
全是 `127.0.0.1` 说明 `HUB_TRUSTED_PROXIES` 没配或配错了——
此时限流按隧道计，一人用满额度所有人被连坐。

**关闭**：`tailscale funnel reset --https=443`

### 方案 B：Cloudflare Tunnel（有域名时）

配置见 `deploy/cloudflared-config.yml`。要点：

1. `cloudflared tunnel create learninghub` → 生成 tunnel UUID 与凭据文件
2. `cloudflared tunnel route dns learninghub hub.example.com`
3. 把配置里的占位符换掉，装成 Windows 服务：

```powershell
cloudflared.exe service install
```

**与 Funnel 的一个关键差异**：cloudflared 回源时会**保留客户端自己写的
`X-Forwarded-For`**，真实客户端 IP 放在 `CF-Connecting-IP`。
服务端两种都认（且只认受信代理发来的），但 `HUB_TRUSTED_PROXIES`
在 Cloudflare 场景下要按**回源 IP 段**配，官方列表会变：
<https://www.cloudflare.com/ips-v4>

### 方案 C：Caddy 直连

配置见 `deploy/Caddyfile`。**80/443 必须空闲**——若被 IIS 或别的服务占用，
改用方案 A 或 B。

## Step 5：防火墙

```powershell
.\firewall-rules.ps1 -Action Apply      # 只开 80/443（22 按需 -OpenSSH）
.\firewall-rules.ps1 -Action Show       # 复查 8637 有没有被意外放行
```

**8637 永远不放行**。隧道方案下服务只监听 `127.0.0.1`，根本不需要开端口；
直连方案下也只需要 80/443。

`Show` 会做一次深度检查（**五条判定**，约 1–2 分钟）：只有
「Inbound+Enabled+Allow / TCP / 端口覆盖 8637 / 来源是公网 / **无程序作用域**」
同时成立才算真的暴露。少最后一条会把 43 条 Windows 自带规则
（`raserver.exe`、`svchost.exe` 等，全是程序作用域）误报成泄漏。

## Step 6：备份

```powershell
.\backup-data.ps1 -DataDir C:\LearningHub\data -BackupRoot D:\LearningHub-backups
```

产出 `<BackupRoot>\LearningHub-data-YYYYMMDD-HHMMSS.zip` + 同名 `.manifest.txt`
（逐文件 SHA256），按 `-RetentionDays`（默认 30）清理旧包。

用任务计划程序每日跑（示例：每天 03:17）：

```powershell
$action = New-ScheduledTaskAction -Execute 'powershell.exe' `
    -Argument '-NoProfile -ExecutionPolicy Bypass -File C:\LearningHub\backup.ps1 -DataDir C:\LearningHub\data'
Register-ScheduledTask -TaskName 'LearningHub-Backup' -Action $action `
    -Trigger (New-ScheduledTaskTrigger -Daily -At 3:17am)
```

**恢复**（见 `restore-data.ps1`）：

```powershell
.\restore-data.ps1 -BackupFile D:\LearningHub-backups\LearningHub-data-20261021-031700.zip `
    -DataDir C:\LearningHub\data -Force
```

恢复前会逐条校验 SHA256，**校验不过就整体拒绝，目标目录一个字节都不动**。
目标目录非空且没给 `-Force` 也会拒绝——覆盖数据目录没有撤销按钮。
恢复完所有已登录设备都要重新登录（`sessions.json` 是旧版本）。

## Windows 平台已知坑

这几条都是本项目**实际踩过**的，不是通用建议。

### 1. PowerShell 5.1 读无 BOM 的 UTF-8 `.ps1` 会按 cp936 误读

**症状**：脚本里明明括号配平、语法没问题，解析器却报一堆
「缺少右 `}`」「Try 语句缺少 Catch」「字符串缺少终止符」，
而且**行号是乱的**（报的位置比实际错误位置靠前）。

**原因**：Windows PowerShell 5.1 对没有 BOM 的 `.ps1` 一律按
**ANSI 代码页**（中文 Windows 是 cp936）解析。GBK 解码器会把夹在中文里的
`\n` 当成 trail byte 吃掉——实测一个 291 行的脚本被合并成 256 行，
然后行号全错。

**解法**：**所有 `.ps1` 必须存成 UTF-8 with BOM**。
`deploy/` 下五个脚本与 `server/build-version.ps1` 都已带 BOM。

**注意它和 `.bat` 的区别**：`.bat` 里写中文会**立刻**炸（REM 行被拆成
bogus 命令）；`.ps1` 里写中文不会立刻报错，而是**安静地改行号**——
后者阴险得多。所以 `build-exe.bat` 的注释一律用英文。

### 2. `PYTHONIOENCODING` / `PYTHONUTF8` 对打包 exe **无效**

**症状**：设了 `PYTHONIOENCODING=utf-8`，exe 输出的还是 cp936；
三种环境（不设 / `PYTHONIOENCODING` / `PYTHONUTF8`）输出的字节**完全相同**。

**原因**：PyInstaller 的 bootloader 在解释器初始化之前就接管了标准流，
环境变量来不及生效。

**解法**：打包内置 runtime hook `server/pyi_rth_utf8_io.py`，
在入口脚本之前把 `stdout`/`stderr` 的 `reconfigure(encoding="utf-8")`。

**这不只是美观问题**：代码库大量中文 `print()`，标准流编码跟随控制台代码页。
一旦服务跑在非中文 Windows 上，`main.py` 启动横幅那句中文 `print`
会抛 `UnicodeEncodeError`——**整个服务起不来，且没有任何日志**。
固定 UTF-8 后输出与机器区域设置彻底解耦。

**代价**：日志文件变成 UTF-8。中文 Windows 的记事本默认按 ANSI 打开会显示乱码，
用 VS Code 或把记事本切成 UTF-8 即可。两害相权选"永不崩"。

### 3. GUI 子系统的 exe 没有 stdout/stderr

`console=False` 打出来的 exe 是 GUI 子系统进程，**没有标准流句柄**。
NSSM / sc.exe 的日志重定向会得到两个永远为空的文件，排障时等于瞎子。

**解法**：服务专用那个 exe 用 `console=True`（`LearningHubSvc.exe`），
再由 runtime hook 在设了 `HUB_SERVICE_LOG_DIR` 时把标准流 tee 到文件。

**三套日志各管一段，不重叠**：

| 文件 | 内容 |
|---|---|
| `<DataDir>\server.log` | uvicorn access/error（2MB×3 轮转、token/sig 已打码） |
| `<LogDir>\service-stdout.log` | 启动横幅（数据目录、端口、手机该填的地址） |
| `<LogDir>\service-stderr.log` | 早期崩溃、Python 警告 |

### 4. `.spec` 里写 `distpath` 无效

PyInstaller 6 只在 spec 命名空间里注入**只读**的 `DISTPATH`，**不读** spec 里的
`distpath` 变量——`CONF['distpath']` 在 exec spec 之前就由命令行参数定好了。
产物照样落到 `./dist`。

**解法**：`--distpath` 只能写在命令行上，所以由 `build-exe.bat` 钉死。

### 5. `Compress-Archive` / `Expand-Archive` 会污染日志

无控制台环境（任务计划程序、stdout 重定向到文件）下，这两个 cmdlet
**仍然把进度条写进输出流**，一大片 `正在创建存档文件…[oooo]` 会把日志冲爆，
且带回车覆盖，事后无法阅读。

**解法**：用 `[System.IO.Compression.ZipFile]::CreateFromDirectory` /
`ExtractToDirectory`，零依赖、更快、无噪音。

### 6. `[CmdletBinding(SupportsShouldProcess)]` 会自动加 `-WhatIf`

再显式写一个 `[switch]$WhatIf` 会直接报
「对命令多次定义了名为 WhatIf 的参数」。自动那个同样会置 `$WhatIf` 变量，
判断照常成立。

### 7. 隧道改写 Host 头 → 前端同源判断

Caddy / cloudflared 都会改写或透传 `Host`。前端的 CORS 白名单里**没有公网域名**，
所以 `Host` 一旦被改成上游地址，页面（`https://hub.example.com/app`）与
API（`https://127.0.0.1:8637`）就不同源了，浏览器直接拦。

**解法**：反代侧保持 `Host` 原样（见 `deploy/Caddyfile` 里的 `header_up Host`）。
隧道方案下页面与 API 同源，不触发 CORS，所以更不能改 Host。

### 8. Android APK 的服务器地址是 `http://`，走 https 需要手工填

`web/src/api/server.ts` 里 UDP 自动发现拼的是 `http://<ip>:<port>`。
用隧道域名时自动发现**不适用**（那是局域网广播），需要在 App 里手工填
`https://<你的地址>`。HTTP 页面访问 HTTPS API 是允许的（反过来不行），
所以这条路走得通。
